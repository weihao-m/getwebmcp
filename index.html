5-Minute Integration

Add WebMCP to your site.

Drop in the standard declaration. Browser agents discover and invoke your tools automatically. 

<!-- 1. Declare tool capabilities in your <head> -->
<meta name="webmcp-support" content="v1.0">
<meta name="webmcp-tools" content="search_products, create_order">

<!-- 2. Expose the native execution handler -->
<script>
  window.webmcp = window.webmcp || { tools: [] };

  window.webmcp.tools.push({
    name: "search_products",
    description: "Search in-stock products by query and maximum budget",
    parameters: {
      type: "object",
      properties: {
        query: { type: "string" },
        maxPrice: { type: "number" }
      },
      required: ["query"]
    },
    handler: async ({ query, maxPrice }) => {
      const results = await window.app.catalog.search({ query, maxPrice });
      return { count: results.length, items: results };
    }
  });

  // Signal ready state to AI browser agents
  window.dispatchEvent(new CustomEvent("webmcp:ready"));
</script>

Questions & Answers

Frequently Asked Questions

What is WebMCP?

WebMCP adapts the Model Context Protocol directly for browser web pages. Instead of requiring server-side daemon installations, front-end web applications declare structured tools that AI browser agents can discover and call on behalf of the user.

How is WebMCP different from server MCP?

Server MCP connects LLMs to local filesystems and backend databases. WebMCP runs inside the client DOM with full access to user authentication, cookies, and live front-end application state.

Does WebMCP require any browser extensions to work?

For websites, no — any standard web application can expose WebMCP tools with simple JavaScript. For users, any agent (like Dassi, Claude Computer Use, or custom AI extensions) can call WebMCP tools out of the box.
